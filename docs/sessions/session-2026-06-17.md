## Decisiones importantes
- Se adopto Docker como unico runtime soportado en produccion.
- Se abandono el rollback al servicio host legacy como camino operativo soportado.
- Se decidio etiquetar el checkpoint estable sobre el commit realmente validado en produccion (`b57be0f`) y dejar la documentacion posterior en un commit separado.
- Se definio que la proxima etapa operativa sera una sesion en modo tutor, con comandos ejecutados por el usuario bajo guia paso a paso.
- Se definio que el procedimiento de rotacion de credenciales del panel debe cubrir dos variantes:
  - rotacion normal sin reinicio
  - rotacion forzada con reinicio para invalidar sesiones activas

## Problemas encontrados
- El host sigue teniendo un `headless boot issue`: no es seguro depender de reboots remotos sin monitor conectado.
- El servicio host legacy `whatsapp-scheduler.service` ya no es un rollback confiable porque el host no conserva un binario local de Chromium operativo.
- Durante la validacion del backup por SSH, `sudo` no fue usable en modo no interactivo.
- El shell remoto del usuario no tenia `npm`/`node` en `PATH`; para reproducir el unit file hubo que inyectar el `PATH` de `nvm`.
- Durante el endurecimiento recursivo de permisos aparecio un lock transitorio de Chromium en `.wwebjs_auth`, resuelto con una pasada tolerante posterior.
